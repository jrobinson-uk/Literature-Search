Citation Crawl — pipeline runs Venue sweep → Keyword pass → Backward pass → Forward pass → Backward pass (again) → final abstract retry sweep, each writing to its own sheet.

1. Seeds

By default, seeds come entirely from the keyword pass (Phase 1) below — it searches Semantic Scholar using your filter terms and keeps whatever passes the filter. Hand-picking specific papers here is optional and adds them on top of (not instead of) the keyword pass's own discoveries.

2. Pipeline Settings ▶

Name this crawl — it becomes the sheet tab name.

Phase 0 — Venue sweep. Enumerates the full publication record of these venues (comma or newline separated — matched fuzzily against Semantic Scholar's own venue names, e.g. "SIGCSE" alone matches its full canonical name) within the year window, through the filter below. Leave the list empty to skip straight to the keyword pass.

Phase 1 — Keyword pass. Target seed count via paginated Semantic Scholar search (a relevance-sorted sweep and a date-sorted sweep, no year floor of its own) — combines terms across your positive filter groups below automatically.

If the keyword pass collects fewer seeds than this percentage of the target, the crawl stops with a "Shortfall" status instead of silently continuing to backward/forward with a thin seed set — click "Resume v2 Crawl" to continue anyway once reviewed.

Log non-matches Checked = also record FALSE candidates from that phase (for audit). Unchecked (default) = only log matching papers. Venue sweep is exhaustive by design and usually the noisiest — leave it unchecked unless you specifically want to audit what it's excluding.

Pipeline order is fixed: venue sweep → keyword pass → backward pass → forward pass → second backward pass → final abstract retry sweep. Backward runs twice — once over the venue/keyword seeds, again after forward completes so forward-discovered matches get their own references pulled too. None of these phases are optional any more; they're the default pipeline.

Backward runs to the same "Max depth" as forward — only papers whose Filter Match is TRUE expand (REVIEW rows are harvested but never expanded either direction — see the Filter section below).

Abstract resolution stays Semantic Scholar + OpenAlex only, but persists for longer (more retries per lookup) and runs one final retry sweep over any still-missing abstracts before the run completes.

3. Filter ▶

Each card is an AND condition; terms within a card are OR'd. Tick NOT for a group, then choose what tripping it means: Exclude (hard veto — Filter Match becomes FALSE) or Flag for review (Filter Match becomes REVIEW — the paper is kept and harvested, but never queued for backward/forward expansion, pending human triage). At least one non-NOT group with terms is required — the keyword pass searches on these.

Guard phrases (optional, comma or newline separated): suppresses a term match when its only occurrence is inside one of these phrases — e.g. add from scratch so a bare "Scratch" term doesn't match "trained from scratch".
